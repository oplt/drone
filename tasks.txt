# DRONE PLATFORM IMPROVEMENT ROADMAP
# Cursor execution plan — ordered from easiest / lowest-risk to hardest / highest-dependency

# Purpose:
#   Convert the architecture/product audit into an implementation backlog Cursor can execute phase by phase.
#
# EXECUTION RULES FOR CURSOR
# --------------------------------------------------------------------
# 1. Work in phase order. Do not start a task whose dependencies are incomplete.
# 2. Before modifying code, inspect the referenced files and confirm the current implementation.
# 3. Prefer small, reversible commits. One logical task per commit where practical.
# 4. Do not replace working architecture merely to match this roadmap.
# 5. Preserve existing APIs and URLs unless the task explicitly requires migration.
# 6. Add or update tests for every behavior change.
# 7. Run relevant backend/frontend tests, linting, type checks, and build checks after each task.
# 8. For performance tasks, measure before and after. Do not merge speculative optimizations.
# 9. For ML changes, preserve dataset/model reproducibility, immutable dataset versions,
#    model checksums, audit history, and human approval gates.
# 10. For agriculture claims, preserve the current evidence-first policy:
#     visual evidence != diagnosis unless the model/data contract explicitly supports diagnosis.
# 11. Keep accessibility behavior when replacing or restructuring map/review interfaces.
# 12. If a task uncovers a blocking architectural issue, document it before expanding scope.
#
# COMPLEXITY
#   XS = very small / isolated
#   S  = small
#   M  = medium
#   L  = large
#   XL = architectural / multi-system
#
# PRIORITY
#   P1 = high-value / near-term
#   P2 = important after P1
#   P3 = defer until demand or scale justifies it
#
# --------------------------------------------------------------------
