[P0][High][S] Agriculture queue consumers missing from compose — DONE (Top 10 #1)
Problem: See Top 10 #1. Beat schedules agriculture.retention_cleanup hourly onto agri exports
  queue with no listener in docker-compose.yml.
Affected: docker-compose.yml; celery_app.py task_routes; agriculture_tasks.py
Evidence: compose --queues= lists have zero agriculture-* entries; celery_app maps
  agriculture.stage.* → CELERY_AGRICULTURE_QUEUES.
Recommended: Add worker service(s) for agri queues (or temporarily route agri → default with
  explicit comment + rate limits). Prefer dedicated GPU/CPU workers for inference stages.
Expected benefit: Jobs complete in local/prod compose parity.
Implementation notes: Match concurrency=1 for rgb_inference/segmentation; higher for ingest.
Validation: docker compose run enqueue + observe task success; CI smoke optional.
Done: worker-agriculture-ingest + worker-agriculture-inference in docker-compose.yml.

[P0][High][S] live_advisory blocks API event loop — DONE (Top 10 #3)
Problem: See Top 10 #3. CPU work on async path; also raises 422 on empty advisory via
  ValueError — OK — but lag affects unrelated routes on same uvicorn worker.
Affected: modules/agriculture/api.py live_advisory
Evidence: Lines 721-725: decode + process_one without run_blocking/to_thread.
Recommended: await run_blocking(processor path); TTL/LRU for _live_processors; metric gauge
  for map size.
Expected benefit: Event-loop lag stable under live frame spam.
Validation: observability event_loop_lag; unit test that run_blocking is used (or mock).
Done: routers/live.py run_blocking; routers/common.py TTL/LRU max 64; agriculture_live_processors
  gauge; test_agriculture_live_advisory.py.

[P1][High][S] Video analysis worker loop single-flight race — DONE
Problem: _run_on_worker_loop raises RuntimeError if loop.is_running() — concurrent tasks on
  same process fail hard instead of queuing.
Affected: entrypoints/workers/video_analysis_tasks.py:26-31
Evidence: Explicit raise; worker concurrency often 1 which masks issue until misconfig.
Recommended: Serialize via asyncio.Lock / queue on WorkerLoopState; or process-per-task.
Expected benefit: No spurious task failures under concurrency>1.
Validation: force concurrency=2 in test worker; both jobs complete.
Done: WorkerLoopState._run_lock serializes run(); run_coroutine_threadsafe when loop running;
  test_worker_loop_state_run_serializes_concurrent_threads.

[P1][Medium][S] MJPEG stream generator may leak HTTP connections — DONE
Problem: infrastructure/camera/recording.py requests.get(stream=True) without timeout;
  abandonment may leave sockets open.
Affected: infrastructure/camera/recording.py mjpeg_stream / wait_for_stream
Evidence: requests.get(..., stream=True); time.sleep(2) wait loop; AutoAddPolicy SSH.
Recommended: timeout=(connect, read); context-managed Response.close; replace AutoAddPolicy
  with known_hosts verification for prod.
Expected benefit: No FD leaks on flaky Pi cameras.
Validation: force generator close mid-stream; assert no growth in open FDs.
Done: _open_http_stream context manager; prod RejectPolicy SSH; test_camera_recording.py.

[P2][Medium][S] Warehouse provisional mapping / mapping stack process globals — DONE
Problem: Process-local dict/process handles (_EPOCHS, mapping stack process refs) lost across
  API replicas and never trimmed → stale state / leaks.
Affected: modules/warehouse (provisional_mapping.py _EPOCHS; mapping_stack_lifecycle)
Recommended: Redis/DB-backed epoch state or explicit TTL cleanup on flight end.
Expected benefit: Multi-replica correctness.
Validation: two API processes disagree without shared store (document or fix).
Done: _EPOCH_TTL_S eviction + end/clear_provisional_epochs; clear on mapping stack shutdown;
  test_provisional_epoch_ttl_and_cleanup. Multi-replica still process-local by design — epochs
  are ephemeral flight hints only; shutdown + TTL prevent leaks on single replica.
